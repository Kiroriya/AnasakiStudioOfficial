# Core gaps found while porting the built-in plugins (phase 7)

Each entry: what was missing, why parity needed it, and the **generic** core joint that now covers it (any JS plugin
or Site Code may use it; reference: `docs/site-code.md` → "Joints for the official plugins (phase 7)",
`backend/internal/sitecode/anasaki.d.ts`). All entries are resolved; the official plugins use the joints and their
tests (`backend/internal/api/official_*_test.go`, joint tests in `code7_test.go`) check the parity items.

## seo · redirects · maintenance (port A)

### A1. JS plugins cannot read their manifest `settings` — ✅ resolved
- **Was:** the manifest `settings` values (Plugins → plugin → Settings, `plugin_packages.settings`, where the
  migration maps the built-ins' options with the same keys) were not reachable from plugin code.
- **Joint:** `site.settings(key)` in a plugin reads, in this order: the saved manifest value (typed; an empty text
  counts as unset) → Site code → Settings `<id>.<key>` → the manifest default. `site.settings()` returns everything.
- **Plugins:** seo, maintenance, forms, custom-code read their settings from Plugins → Settings; the tests save them
  there (`offBPkgSettings` / `offAPkgSettings`).

### A2. Admin pages cannot save plugin settings — ✅ resolved
- **Joint:** `site.saveSettings(values)` — partial, validated against the manifest, audited; admin page code only
  (render / action / download) and only for `manage_options`.
- **Plugins:** seo — the "Site-wide defaults" form on the SEO page (`seo:saveDefaults`); maintenance — the settings
  form on its page (`maintenance:saveSettings`, was the generic screen `/p/maintenance`).

### A3. No site information for code — ✅ resolved
- **Joint:** `site.info()` → `{title, tagline, url, language, timezone, adminEmail?}` (`adminEmail` for Site Code
  and plugins with the `mail` scope); `siteTagline` in the page object.
- **Plugins:** seo `%tagline%` and the admin previews (no more cached title); maintenance shows the site name and
  uses the site's language; forms falls back to the site title / admin email.

### A4. Per-post SEO in the post editor — ✅ resolved
- **Joint:** `site.fields(type, fields)` in JS plugins with the new scope `content-fields` (post meta
  `<id>.<key>`, one editor panel per plugin `section.plugin-fields[data-plugin]`), `site.meta(postId)` /
  `site.setMeta(postId, values)`, `meta.<id>.<key>` in `db.posts.list` where/orderBy.
- **Plugin:** seo registers `seo.title|description|image|noindex` for posts and pages — the editor's SEO panel is
  back (authors on their own posts); the SEO admin page and `legacyImport` write the same meta (the plugin no longer
  has its own `p_seo_meta` table). The Angular editor hides the old built-in SEO card when the plugin panel exists.

### A5. Admin-wide notice — ✅ resolved
- **Joint:** `site.adminNotice(fn(ctx) → {level, text, link?} | null, {access})` (scope `admin-pages`),
  `GET /api/v1/code/admin-notices`, rendered in the admin shell (`#admin-notices .admin-notice`).
- **Plugin:** maintenance — "Maintenance mode is on" + "View the real site (bypass link)" for administrators.

### A6. Headers on a continued request — ✅ resolved
- **Joint:** a middleware result `{headers: {...}}` (only that key) continues the request with allow-listed headers
  (`Cache-Control`, `Vary`, `X-Robots-Tag`, …).
- **Plugin:** maintenance sends `Cache-Control: no-store` with real pages served to bypass-cookie holders.

### A7. Sitemap cache — ✅ resolved
- **Joint:** core caches the rendered `/sitemap.xml` (5 min) keyed by published content, category links, options
  and, for the units filtering `sitemap.urls`, their versions, manifest settings and data writes.

### Not gaps, but not identical
- maintenance: the bypass cookie is `pl_maintenance_bypass` (plugin cookies are namespaced) instead of
  `anasaki_bypass` — testers re-open the bypass link once after the migration. A signed-in CMS user's request (admin
  bearer token, e.g. previews) is never blocked (`ctx.isAdminUser`). The generated bypass key lives in the
  plugin's table `p_maintenance_state` (the built-in kept it in its settings).
- redirects: the 404 log is written per request from `site.afterResponse` (queued, after the response) instead of
  in-memory batches every 5 s; the admin page also offers 307/308 and editing (the API had them, the old page did
  not); the old hint "end with * to match a prefix" was wrong (never implemented) and is replaced.
- admin pages live under the Site Code admin-pages menu (`seo:seo`, `redirects:redirects`,
  `maintenance:maintenance`), not the old routes `/seo`, `/redirects`, `/p/maintenance`.
- seo: the admin previews use the site URL from `site.info()`; per-page values are post meta (`seo.*`),
  so they travel with the post in the export / import tool.

## analytics · forms · cookie-consent · custom-code (port B)

A1 and A3 apply here too: custom-code reads `headCode` / `bodyCode`, forms reads `notifyEmail` / `siteTitle` from
Plugins → Settings; forms uses `site.info().title` / `adminEmail` (scope `mail`) when they are empty.
cookie-consent was never affected (its banner is the package's `bodyEnd` template rendered with the manifest
settings).

### B1. Server-rendered package blocks for JS plugins — ✅ resolved
- **Joint:** `site.block(type, {label, icon, props, options(ctx), render(ctx, props) → html | {html, css},
  script?, cache?})`: listed with the package blocks (`GET /api/v1/blocks`, dynamic select options), previewed by
  `POST /api/v1/blocks/render`, rendered on the server in the page's code session; HTML sanitised (forms and inputs
  kept) unless `head-scripts`, CSS scoped under `.pb-<plugin>-<block>`, `script` = a package asset loaded with it.
- **Plugin:** forms — the block renders the chosen form's markup on the server (works without JavaScript,
  indexable) and the property panel lists the forms (`#id — name`); the node is unchanged, so pages made with the
  built-in keep working; `assets/form.js` adds the fetch submission.

### B2. Client address and host for routes / afterResponse — ✅ resolved
- **Joint:** `request.ip` / `request.host` in every request ctx; `host` + `headers` (`purpose`, `sec-purpose`,
  `x-moz`, …) in `ResponseInfo`.
- **Plugins:** forms rate-limits inside the submit route, after the honeypot (only real submissions count, like the
  built-in; the middleware is gone); analytics drops prefetches and internal referrers from `ResponseInfo` (no
  more middleware markers / host learning).

### B3. Emitting a core event name — ✅ resolved
- **Joint:** manifest `code.eventAliases` (`{"forms.submitted": "form.submitted"}`): the plugin's own event is also
  delivered under the alias (site.on in every unit, service plugins, package webhooks); CMS namespaces and other
  plugins' prefixes are refused.
- **Plugin:** forms — listeners of the documented `form.submitted` keep working.

### B4. Outbound webhooks to arbitrary URLs — ✅ resolved
- **Joint:** `http.webhook(url, event, data, {secret?})` (new scope `webhooks`): queued POST to any public http(s)
  URL, `X-Anasaki-Event`, optional `X-Anasaki-Signature: sha256=…`.
- **Plugin:** forms sends each form's webhook with the built-in body `{event: "form.submitted", form: {id, name},
  submissionId, data, submittedAt}`.

### B5. Dashboard widgets — ✅ resolved
- **Joint:** `site.dashboardWidget(id, {label, icon, access, height, render})` (scope `admin-pages`),
  `GET /api/v1/code/dashboard-widgets`, sandboxed card at `/ext-ui/code/<ticket>/widget/<id>`
  (`section.dash-widget[data-id] iframe.dash-widget-frame` on the dashboard).
- **Plugin:** analytics — "Visitors, last 7 days" (totals + daily chart) for administrators and editors.

### B6. Site layout for plugin route pages — ✅ resolved
- **Joint:** route / middleware result `{page: {title, html}, status?}` or `response.page({title, html}, status)`.
- **Plugin:** forms — the failed classic post and the standalone form page `/forms/<id>` show inside the site's
  header and footer.

### B7. Aggregates in fallback mode — ✅ resolved
- **Joint:** `selectCount / selectCountDistinct / selectSum / selectAvg / selectMin / selectMax` in both database
  modes (SUM/AVG as numbers).
- **Plugin:** analytics' top pages / referrers use `SUM … GROUP BY` everywhere (the JS summing fallback is gone).

### B8. Column collation — ✅ resolved
- **Joint:** `t.string(...).binary()` / `.collation('utf8mb4_bin' | 'utf8mb4_unicode_ci' | 'utf8mb4_general_ci')`.
- **Plugin:** analytics migration `002_case_sensitive_paths` — `/About` and `/about` are counted apart again.

### B9. Settings value size — ✅ resolved (with A1)
- custom-code's `headCode` / `bodyCode` come from the manifest settings (maxLength 100,000, stored in a JSON
  column); Site code → Settings values stay limited to 20,000 characters.

### Not gaps, but not identical (port B)
- analytics: views are written per request from `site.afterResponse` (queued) instead of 3-second batches; the page
  title comes from `ResponseInfo.title`; at summary time posts / pages are re-titled from `db.posts` (path = post
  URL), while the home page and categories keep the stored title. The admin page is `analytics:stats` (administrator
  + editor; custom roles that had `view_stats` need an Access override) and draws kit bar charts (views, visitors)
  with a table view instead of the Angular line chart. The old JSON endpoint `GET /api/v1/analytics/summary` is the
  export `summary(days)` (same JSON).
- forms: admin page `forms:forms` (administrator + editor; custom roles with `edit_pages` need an Access override);
  the admin JSON API under `/api/v1/forms/…` is replaced by the page's actions (`forms:list|save|delete|submissions|
  markRead|deleteSubmission`) and its CSV download. The block posts `application/x-www-form-urlencoded` (multipart
  and JSON bodies are still accepted); its client script is a package asset (`assets/form.js`) instead of inline
  JavaScript. The core migration could copy the option `admin_email` to `notifyEmail` (not needed: empty =
  `site.info().adminEmail`).
- cookie-consent: fixed a Go bug — the banner's inline `display:flex` overrode `hidden`, so it never disappeared;
  `#anasaki-cc[hidden]{display:none!important}` now hides it after a choice and for returning visitors.
